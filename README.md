# Credit Card Fraud Detection Using Machine Learning

An academic machine-learning project that estimates whether a credit-card transaction may be fraudulent. This repository includes a Streamlit inference application and a saved XGBoost model.

## Project objectives
- Explore labelled credit-card transaction data.
- Prepare a consistent feature pipeline for inference.
- Compare Logistic Regression and XGBoost using fraud-focused metrics.
- Demonstrate predictions through an interactive Streamlit interface.

## Dataset
The project uses the public [Kaggle Credit Card Fraud Detection dataset](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud). The target column is `Class`: `0` = legitimate and `1` = fraud. Features include `Time`, `Amount`, and anonymized PCA components `V1`–`V28`.

Download the CSV from Kaggle and keep it locally as `data/creditcard.csv`. The raw dataset is not committed to this repository.

## Tools and libraries
Python, Pandas, NumPy, scikit-learn, XGBoost, Matplotlib, Seaborn, Joblib, Jupyter Notebook, and Streamlit.

## Run locally
1. Clone the repository:
   ```bash
   git clone https://github.com/ishacodes11/credit-card-fraud-detection.git
   cd credit-card-fraud-detection
   ```
2. Create and activate a virtual environment (recommended).
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Start the dashboard:
   ```bash
   python -m streamlit run app.py
   ```

## Reproduce the experiments
Open `notebooks/credit_card_fraud_detection.ipynb`, place the Kaggle CSV in `data/creditcard.csv`, and run the cells in order. The notebook demonstrates data inspection, a stratified train/test split, train-only scaling, Logistic Regression, XGBoost, exploratory Isolation Forest and Local Outlier Factor baselines, and evaluation plots.

The notebook trains a fresh model. Its metrics may differ from the previously saved model's metrics below. Do not overwrite the dashboard's existing model artifacts unless you have checked the new model and confirmed app compatibility.

## Limitations
- This is an educational prototype and does not connect to a live payment network or bank.
- `V1`–`V28` are anonymized components and are not directly interpretable customer attributes.
- User-entered feature values in the dashboard are illustrative; arbitrary values may not represent a realistic transaction.
- A model probability is an estimate, not proof that a transaction is fraudulent.
- Performance may change on new data or under distribution shift.

## Responsible use
Do not use this prototype to approve, reject, or block real financial transactions. Production use would require independent validation, monitoring, security, privacy safeguards, human review, and compliance controls.
